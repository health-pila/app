# 앱 정적 파일 업데이트

사용자는 제공받은 파일과 `images`, `tools` 폴더를 기존 프로젝트에 복사한 뒤 평소처럼 커밋·푸시합니다. 서버, Supabase 쿼리, 함수 배포, 별도 유료 서비스는 필요하지 않습니다.

## 이후 수정 파일을 준비하는 개발자/에이전트

1. 기능 파일을 수정합니다. 화면 전체의 `?v=` 값을 일괄 교체하지 마세요.
2. `python3 tools/build-assets.py 289`처럼 배포 번호를 지정해 실행합니다. Python 표준 라이브러리만 사용하며 실제 앱 실행에는 Python이 필요하지 않습니다.
3. 생성된 `app-assets.js`, `service-worker.js`, 변경된 HTML을 기능 파일과 함께 전달합니다. 수정하지 않은 리소스의 해시는 유지됩니다.
4. `app-assets.js`와 `service-worker.js`는 생성물입니다. 로더는 `tools/app-assets-runtime.js`, 캐시 동작은 `tools/service-worker-template.js`를 수정하고 다시 생성하세요.

브라우저는 동일한 내용 해시의 리소스를 재사용합니다. HTML은 네트워크를 먼저 확인하며, 설치된 화면이 있을 때 느린 네트워크는 최대 1.2초 후 저장된 화면을 표시합니다. 업데이트 설치는 별도로 진행됩니다. 초기 화면에 쓰지 않는 관리자 모듈과 이미지 등은 최초 캐시에 포함하지 않습니다.

캐시에 저장하는 것은 명시된 정적 파일뿐입니다. Supabase, 회원 데이터, 로그인·결제 복귀의 쿼리 URL은 이 캐시로 저장하거나 대신 응답하지 않습니다. 이전 페이지와의 호환을 위해 기존 캐시 및 이미 검증된 해시 파일을 강제로 삭제하지 않습니다. 브라우저가 저장 공간을 회수하면 네트워크로 다시 준비합니다.

v288에는 v287의 출석·회원권 안내 문구 수정도 포함되어 있습니다. 회원의 기기에서는 첫 캐시 구조 전환 시 파일 준비가 발생하며, 이후 작은 업데이트에서 재사용 효과를 확인할 수 있습니다.

로컬 검증: 파일 해시/SRI 일치, 동일 배포 재설치 시 0개 다운로드, 작은 다음 배포 시 변경 파일만 준비, 오프라인 저장 화면, 인증·결제 URL 캐시 제외, 관리자 지연 로드와 로그아웃 중단, 제한 회원 화면, 신청서 로드 실패 후 재시도, 숨긴 PT 복원 경로, 진단 기록 보존을 확인했습니다. 실제 회원 기기·Supabase 서버의 실행 시간을 측정한 결과는 아닙니다.
