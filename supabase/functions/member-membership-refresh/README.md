# 회원권 직접 갱신 · v345

배포 순서: 설치 SQL → 새 Edge Function → 확인 SQL → 앱 파일.

1. Supabase SQL Editor에서 프로젝트 루트의 `SETUP-v345-membership-refresh.sql` 전체를 실행한다.
2. Edge Functions에서 이름이 **member-membership-refresh**인 새 함수를 만든다. 이 폴더의 `index.ts` 전체를 붙여 넣는다. 외부 import나 별도 라이브러리 파일은 없다.
3. 이 새 함수의 **Verify JWT**는 끈다. 함수 내부에서 실제 Auth 서버로 사용자 토큰을 확인하고, 요청한 사용자와 일치하는 본인의 회원권만 처리한다.
4. 기존 프로젝트의 `SUPABASE_URL`, 서버 키, `BROJ_GROUP_ID`, `BROJ_API_KEY`를 사용한다. 기존 Secrets가 프로젝트에 등록돼 있으면 새로 입력하지 않는다. 기존 `broj-attendance-sync` 함수를 교체하거나 정기 수집 설정을 변경하지 않는다.
5. `/functions/v1/member-membership-refresh/health`를 열어 `ok: true`, `revision: 345`, `broj_requests: 0`을 확인한다. 이 경로는 브로제이 조회를 실행하지 않으며 SQL 설치 검증을 대신하지 않는다.
6. SQL Editor에서 `CHECK-v345-membership-refresh.sql`을 실행하고 12개 항목이 모두 true인지 확인한다.
7. 앱 덮어쓰기 파일을 배포한다. 회원 앱을 새로고침하고 운동 기록 → 현재 헬스회원권 만료일 옆의 아이콘을 누른다. 실제 브로제이 조회 한 번을 수행하고 성공한 뒤 앱의 본인 회원권 정보를 다시 불러온다.
8. 새 회원권이 이용 대기인 경우 현재 만료일과 별도로 이용 대기 만료일을 표시한다. 새 결제가 아직 브로제이 회원권에 입력되지 않았다면 갱신해도 만료일은 그대로일 수 있다.
9. 관리자 → 회원 관리 → 회원 선택 → 출석·이용권 → 이용권 확인·앱 이용 관리에서 헬스·필라테스 만료일과 이용 대기 만료일을 확인한다. 관리자 영역은 저장된 최신 정보를 조회하며, 기존 앱 이용 제한을 자동으로 변경하지 않는다.

본인 요청은 60초 간격으로 제한한다. 기존 전역 API 호출 예산과 회원권 lease를 그대로 사용한다. 정기 수집과 겹치거나 호출 예산을 사용할 수 없으면 기존 표시값을 보존하고 재시도 안내를 표시한다. 갱신 실패는 기존 snapshot을 만료·없음으로 바꾸지 않는다.

성공 시 기존 `broj_complete_memberships_with_eligibility`를 통해 회원용 snapshot과 관리자 분류용 snapshot을 함께 저장한다. 기존 분류 규칙, 수집 주기, 이용권 원본, 앱 이용 제한 정책을 재설치하거나 바꾸지 않는다. 삭제 중인 계정과 앱 이용이 제한된 계정의 직접 갱신은 거부한다.

새 임시 요청 상태는 private/RLS 테이블에 보관하며 계정 삭제 시 FK로 함께 제거한다. 브라우저에는 브로제이 키·회원 식별자·서버 전용 lease가 전달되지 않는다.
