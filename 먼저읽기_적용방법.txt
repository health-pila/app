센터앱 v153 — 운동 추가·삭제 및 튜토리얼 종목변경

1. 적용
- 현재 개발 폴더 전체를 먼저 별도로 보관해도 좋습니다.
- ZIP 안의 ‘교체파일’ 폴더를 엽니다.
- 그 안의 8개 파일을 기존 개발 폴더의 같은 위치에 복사하고 덮어씁니다.
- ‘교체파일’ 폴더 자체를 개발 폴더 안에 넣는 방식이 아닙니다.
- ‘참고자료’는 안내·백업용입니다. 앱 폴더에 넣을 필요 없습니다.
- 새 이미지나 외부 라이브러리 설치는 필요 없습니다. v152에서 적용한 이미지 폴더는 그대로 씁니다.
- SQL은 이번 채팅에서 설치·권한 확인까지 완료했습니다. 보관용 SQL을 다시 실행할 필요 없습니다.
- Cursor 소스 제어에 기존 파일 수정 8개(M)가 표시됩니다. 커밋·동기화는 사용자가 진행합니다.
- 권장 커밋명: feat: 패턴별 운동 추가·삭제 및 튜토리얼 종목변경 지원

2. 변경 기능
- 각 패턴의 마지막 카드 아래 ‘+ 운동 추가하기’ 버튼을 표시합니다.
- 기존 운동 선택창에서 전체 운동 검색·부위 필터, 내가 추가한 운동, 새 이름 직접 입력을 재사용합니다.
- 추가 시 세트·횟수·휴식시간을 직접 입력하고 확인 후 저장합니다.
- 공식 운동은 기존 이미지·안내·영상·기록·PT 버튼을 그대로 사용합니다.
- 직접 입력한 운동은 기존 손글씨 아이콘을 쓰고 상세설명·영상 버튼을 숨깁니다.
- 추가한 카드에만 ‘운동 삭제’가 표시됩니다. 원본 운동과 튜토리얼 기본 5종은 삭제하지 않습니다.
- 추가한 카드도 ‘종목변경’이 가능합니다. 추가 카드는 원본 배정 운동이 아니므로 원본 복원 대신 삭제를 제공합니다.
- 튜토리얼 기본 5종도 회원별 종목변경·원본 복원을 사용할 수 있습니다.
- 튜토리얼의 PT 장바구니·담기 버튼은 계속 숨깁니다. 기존 안내 2줄과 신청 버튼을 유지합니다.
- 드래그 및 운동 순서 변경 기능은 이번 버전에 포함하지 않았습니다.

3. 저장 및 기존 데이터
- 원본 루틴 JSON과 기존 교체 설정의 원본 위치를 바꾸지 않습니다.
- 추가 카드는 UUID, 원본 종류, 배정 ID·버전, 패턴으로 구분합니다. 운동 ID나 이름을 카드 식별자로 사용하지 않습니다.
- 추가 순서는 서버 생성 순번을 사용하고 패턴 끝에만 붙입니다.
- 추가 운동 저장소와 튜토리얼 기본 카드의 교체 저장소는 별도입니다.
- 다른 기기에서 로그인하거나 새로고침하면 같은 추가 카드·개인 운동 목록을 조회합니다.
- 이미 열린 다른 기기 화면은 새로고침해 최신 설정을 확인합니다. 새 테이블의 실시간 구독은 추가하지 않았습니다.
- 중량 기록은 기존대로 회원 ID + 실제 운동 ID 기준 5세트 브라우저 저장입니다. 추가 카드 UUID와 분리합니다.
- 동일한 운동을 여러 카드에 넣으면 해당 운동의 기존 5세트 기록을 함께 사용합니다.
- 다른 기기의 중량 기록까지 동기화하는 기능은 추가하지 않았습니다.
- 카드 삭제는 현재 패턴에서만 제거하는 동작입니다. 서버에서는 삭제 표시를 남겨 재시도로 카드가 다시 살아나는 것을 막습니다.
- 개인 운동 목록, 중량 기록, 운동 기록 사진은 삭제하지 않습니다.
- 새 맞춤 루틴 배정 또는 기존 배정의 버전 변경 시 이전 추가·교체 설정을 새 루틴에 적용하지 않습니다.
- 튜토리얼 설정도 맞춤 배정에 자동 적용하지 않습니다. 개인 운동 목록과 기록은 유지합니다.

4. 안전 및 오류 처리
- 저장 함수는 로그인·본인 소유·현재 배정 버전·실제 패턴·운동 ID·설정 범위를 검사합니다.
- 개인 운동 이름 등록과 카드 추가/변경을 한 트랜잭션에서 처리합니다. 실패하면 새 이름 등록도 취소됩니다.
- 같은 카드 UUID의 동일 추가 요청은 중복 저장하지 않습니다.
- 수정·삭제는 change_token을 검사해 다른 기기의 변경을 덮어쓰지 않습니다.
- 저장 성공을 확인하기 전에는 새 카드를 성공한 것처럼 표시하지 않습니다.
- 응답을 확인하지 못하면 ‘저장 상태 다시 확인’ 또는 오류 영역의 ‘다시 불러오기’를 사용합니다.
- 정상 저장/삭제/복원 시 불필요한 성공 안내 영역은 추가하지 않았습니다.
- 추가 설정 조회가 10초 동안 완료되지 않으면 편집을 막고 기본 또는 현재 화면에서 마지막 확인한 설정을 표시합니다.
- 계정 변경·로그아웃·신청/배정 상태 변경 뒤 도착한 이전 응답은 적용하지 않습니다.
- 회원 입력 이름은 textContent로 표시하며 HTML로 해석하지 않습니다.
- 프런트엔드에 service_role 키나 새 비밀키를 넣지 않았습니다.

5. 적용 후 확인할 순서
① 맞춤 루틴의 패턴 1에서 공식 운동을 추가합니다. 마지막에 카드가 붙는지 확인합니다.
② 패턴 2·3과 기존 보너스 패턴에는 그 추가가 적용되지 않는지 확인합니다.
③ 다른 패턴에서 ‘와이드 스쿼트’를 직접 입력하고 설정을 저장합니다.
④ 손글씨 아이콘, 상세설명·영상 숨김, 5세트 중량 기록, PT 희망 종목 이름을 확인합니다.
⑤ 새로고침·로그아웃 후 재로그인·다른 기기에서 같은 회원으로 접속해 추가 카드와 개인 목록을 확인합니다.
⑥ 추가한 카드의 종목을 변경하고 UUID와 기록 연결이 유지되는지 확인합니다.
⑦ 추가 카드를 삭제하고 개인 목록에서 다시 추가해 기존 중량 기록이 남아 있는지 확인합니다.
⑧ 원본 운동에 삭제 버튼이 없고, 기존 종목변경·복원도 정상인지 확인합니다.
⑨ 튜토리얼 계정에서 기본 5종·안내 문구·신청 버튼을 확인하고 종목변경·추가·삭제를 시험합니다. PT 버튼은 없어야 합니다.
⑩ 서로 다른 두 회원의 추가 카드·개인 목록이 분리되는지 확인합니다.
⑪ 테스트 회원에게 새 루틴을 배정한 뒤 이전 추가·교체가 적용되지 않고 개인 목록·과거 기록은 남는지 확인합니다.
⑫ 관리자 PT 신청 목록에서 직접 입력한 운동명이 정확한지 확인합니다.
- 실제 회원의 루틴을 검증 목적으로 바꾸지 말고 테스트 계정을 사용하세요.
- PWA는 배포 후 새 버전을 한 번 받아야 합니다. 앱을 완전히 닫고 다시 열거나 새로고침합니다.
- 이 기능 이후의 운동 안내 콘텐츠 수정은 기존 시트 자동 동기화 경로를 그대로 사용합니다.

6. 로컬에서 완료한 검증
- 신규 SQL 재실행 및 80개 검사: 기존 함수 정의·루틴 JSON 보존, 본인 RLS, 직접 쓰기 차단, 패턴·회원 분리, 저장 충돌, 신규 배정 분리, 이름 등록 원자성 등.
- 실제 SQL을 연결한 Chromium 테스트: 공식/개인 운동 추가·재선택·수정·삭제, 기록 5세트와 이미지 캡처, 개인 이름 PT 신청 및 관리자 표시, 다른 브라우저의 동일 계정 조회.
- 실패 테스트: 추가/삭제 실패 시 카드 상태 유지, 응답 유실 후 재조회, 잘못된 추가 설정 수신 시 마지막 정상 설정 유지.
- 튜토리얼 종목변경·원본 복원·추가·기록·PT 미노출, 맞춤 배정 전환과 기존 데이터 보존.
- 계정 전환·신청 상태 변경 중 지연 응답 무시, 조회 시간 초과 후 복구.
- 콘텐츠 자동 동기화가 추가한 공식 카드의 안내에도 반영됨.
- 모바일 320/390px와 PC 1280px 레이아웃 검사.
- 실제 서비스워커 v152 → v153 캐시 갱신, 로컬 로그인·기록 저장소 유지, 오프라인 정적 파일 로딩.
- 실제 Supabase/실기기에서의 최종 동작은 파일 배포 후 위 순서로 확인합니다. 운영 데이터를 자동 변경하는 테스트는 하지 않았습니다.

7. 되돌리기
- ‘참고자료/변경전_v152’의 8개 파일을 기존 개발 폴더에 덮어씁니다.
- 커밋·동기화 후 앱을 완전히 닫고 다시 열어 이전 화면으로 돌아갑니다.
- 새 Supabase 테이블·함수를 삭제할 필요는 없습니다. v152는 사용하지 않으므로 남겨두면 됩니다.
- 되돌려도 개인 운동 목록과 기록을 삭제하지 않습니다. v153에서 저장한 추가 카드는 DB에 남고 v152 화면에서만 보이지 않습니다.
- 다시 v153을 적용하면 해당 배정 버전의 설정을 조회할 수 있습니다.
- 보관용 SQL을 취소하려고 기존 테이블이나 기록을 DROP/DELETE하지 마세요.
