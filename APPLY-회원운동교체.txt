회원별 운동 교체 — v122 작업 중 추가 기능
기준: v122 + 설명글 14px/#475467 수정 + 사용자 알림음 0.9/종료 시점 0.25초
이번 파일에는 버전 번호를 올리지 않았습니다. 최종 배포 전에 버전을 함께 올려 주세요.

[먼저 알아둘 내용]
- 관리자가 배정한 원본 JSON은 수정하지 않습니다.
- 회원 + 루틴 ID + 배정 버전 + 패턴 번호 + 운동 순서별로 별도 교체 설정을 저장합니다.
- 같은 운동이 다른 패턴에 있어도 각 블록은 따로 변경됩니다.
- 원본 복원은 해당 교체 설정만 삭제합니다. 기존 운동 기록/중량 기록은 삭제하지 않습니다.
- 새 루틴 배정이나 현재 루틴의 JSON 재적용은 새로운 배정 버전을 만듭니다.
  같은 JSON을 그대로 다시 적용해도 회원의 이전 교체는 새 버전에 적용되지 않습니다.
- 기존 설정은 과거 데이터로 남습니다. 기존 루틴/운동 기록도 그대로 남습니다.
- DB에서 루틴 이름만 바꾸는 작업은 교체 설정을 초기화하지 않습니다.
  관리자 앱의 '운동 카드 적용'은 JSON을 저장하므로 같은 내용이어도 초기화됩니다.
- 교체 설정은 Supabase에 저장되어 같은 계정이면 다른 기기에서도 불러옵니다.
  기존 중량 기록은 지금처럼 회원/운동별 브라우저 저장입니다. 기기 간 중량 기록 동기화를 추가한 것은 아닙니다.
- 이미지형 루틴은 그대로 지원합니다. 운동 교체는 JSON 운동 카드에만 표시됩니다.

[적용 순서]
1. 현재 개발 폴더를 백업해 주세요.
2. 기존 센터 앱 Supabase 프로젝트의 SQL Editor에서
   SETUP-member-exercise-replacements.sql 전체를 한 번 실행해 주세요.
   새 보조 테이블 2개, 회원용 RPC 2개, 배정 버전을 만드는 전용 AFTER 트리거/함수를 설정합니다.
   기존 member_routines의 열/JSON/권한 정책과 회원/운동 기록 테이블은 바꾸지 않습니다.
   기존 member_routines에 추가되는 트리거는 새 보조 테이블만 기록합니다.
   SQL은 하나의 트랜잭션입니다. 오류가 나면 중간 단계는 적용되지 않습니다.
   재실행해도 등록된 교체 내역과 배정 버전은 유지됩니다.
3. 다음 앱 파일 6개를 프로젝트 최상위 폴더에 복사해 주세요.
   index.html (교체)
   routine-components.js (교체)
   script.js (교체)
   service-worker.js (교체)
   member-exercise-replacements.js (새 파일)
   member-exercise-replacements.css (새 파일)
   SQL과 이 안내문은 앱 파일로 배포하지 않아도 됩니다.
4. 다른 수정까지 마친 뒤 배포할 때, index.html과 reset-password.html의 ?v=122 및
   service-worker.js의 APP_VERSION을 같은 새 번호로 올려 주세요.
   현재 요청에 따라 이 ZIP의 버전 번호는 v122로 유지했습니다.
5. 커밋/푸시하고 앱을 새로고침해 주세요.
   커밋 메시지 예: feat: persist member exercise replacements per routine assignment

[사용 방법]
- 회원의 운동 카드 하단 '운동 바꾸기'를 누릅니다.
- 현재 종목의 등록된 대체 운동을 먼저 보여줍니다. 현재 운동 자신/없는 운동/미사용 운동은 제외합니다.
- '전체 운동에서 선택'을 열면 운동명 검색과 운동 부위 필터를 사용할 수 있습니다.
- 원하는 운동을 선택하면 원래 운동 → 선택 운동, 주요 부위/난이도/주의 부위를 표시합니다.
- 운동 유형이 같으면 현재 세트/횟수/휴식을 확인창에 불러옵니다. 맞는지 확인 후 조절해 주세요.
- 유형이 다르면 세트/횟수/휴식을 비워 직접 확인·입력하도록 합니다.
  종목별 기본 처방값이 운동 DB에 없어서 임의의 처방을 자동 생성하지 않았습니다.
- 현재 앱의 횟수형 처방 형식을 유지합니다. 입력 범위는 세트 1 ~ 20,
  횟수 1 ~ 1000, 휴식 0 ~ 3600초입니다. 이 범위는 저장 형식의 상한이며 권장 운동량이 아닙니다.
- 확인 체크 후 저장합니다. 서버 저장이 확인된 뒤 카드가 바뀝니다.
- 변경 카드에는 '직접 변경한 운동', 원래 배정 종목, '원래 운동으로 복원'을 표시합니다.
- 복원도 확인창에서 확정합니다. 원래 종목과 원래 세트/횟수/휴식으로 돌아갑니다.
- 전체 운동에서 원래 배정 종목을 선택해도 복원 확인으로 연결됩니다.
- 카드 이미지/상세/영상/중량 기록/기록 캡처/PT 담기는 실제 표시하는 운동 ID로 연결합니다.
- 이미 PT 장바구니에 담아둔 종목은 그대로 유지합니다. 교체 후 '담기'는 새 종목을 담습니다.
- 전체 루틴 안내 원문은 관리자 배정 기준으로 유지합니다.

[저장/네트워크/다른 기기에서의 변경]
- 저장 실패 시 카드를 바꾸거나 성공 안내를 표시하지 않습니다.
- 저장 여부를 확인할 수 없으면 '저장 상태 다시 확인'으로 서버 상태를 먼저 조회합니다.
- 다른 기기가 같은 블록을 먼저 변경했다면 덮어쓰지 않고 충돌 안내를 표시합니다.
- 선택창을 연 사이 새 루틴이 배정되면 이전 배정에 저장하지 않도록 차단합니다.
- 설정 조회가 실패하면 원본 루틴을 표시한다는 안내와 재조회 버튼을 표시하며 변경 버튼은 비활성화합니다.
- 같은 계정으로 다른 기기에 로그인하거나 새로고침/앱 복귀 시 서버 설정을 불러옵니다.
  두 기기를 계속 켜둔 경우 즉시 동시 반영을 보장하는 별도 실시간 구독은 추가하지 않았습니다.
  다시 불러오기/새로고침/앱 복귀로 최신 설정을 확인할 수 있습니다.

[권한 및 운영]
- 두 신규 테이블에 RLS를 적용해 본인 데이터만 조회하게 합니다.
- 테이블 직접 쓰기는 차단하고, auth.uid()로 본인과 현재 배정을 확인하는 RPC로만 저장/복원합니다.
- RPC는 search_path를 고정하고 인증된 사용자만 실행할 수 있습니다.
- 프런트엔드에는 기존 공개 클라이언트를 사용합니다. 관리자 비밀키/service_role 키를 추가하지 않았습니다.
- 새 배정 판단은 수정 시각이 없는 기존 구조에 맞춰 보조 테이블의 UUID 버전으로 처리합니다.
- 서버 RPC의 허용 운동 ID 목록은 현재 exercise-data.js의 활성 39종과 일치합니다.
  새 운동을 DB에 추가하거나 사용 여부를 바꿀 때는 이 SQL의 허용 ID 목록도 함께 갱신해 주세요.
- 기존 정책/테이블 삭제, 기존 데이터 일괄 초기화, 로그인 구조 변경은 없습니다.
