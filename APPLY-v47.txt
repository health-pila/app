v47 관리자 신규 회원 자동 갱신

적용할 파일 (세 개)
- script.js
- index.html
- service-worker.js
현재 프로젝트의 같은 이름 파일에 덮어쓴 후 커밋·푸시합니다.
이 ZIP은 전체 프로젝트 백업이 아닌 교체 파일 묶음입니다.

동작
- 관리자 화면이 보이는 동안 10초마다 가장 최근 가입한 회원 ID 하나만 확인합니다.
- 새 회원이 발견될 때만 기존 회원 목록과 루틴 배정 정보를 다시 불러옵니다.
- 인터넷 연결과 서버 응답이 정상이라면 가입 후 보통 10초 안팎으로 목록에 반영됩니다.
- 관리자 화면으로 돌아오거나 인터넷이 다시 연결되면 가입 여부를 확인합니다.
- 선택한 회원, 검색어, 작성 중인 JSON/이미지/설명과 미리보기는 자동 갱신으로 초기화하지 않습니다.
- 검색어가 남아 있으면 신규 회원도 그 검색 조건에 맞을 때 목록에 표시됩니다.
- 저장/신청 회원 선택 작업 중에는 자동 갱신을 보류하고 이후 다시 확인합니다.
- 자동 조회 실패 시 기존 목록을 유지합니다.
- 로그아웃하거나 회원 화면으로 전환하면 자동 확인을 중단합니다.

설정 및 유지 사항
- Supabase SQL, 권한, Realtime 설정 변경은 필요 없습니다.
- 배포 버전은 index.html 네 곳과 service-worker.js를 모두 47로 맞췄습니다.
- 앱 이름: 전체 이름 ‘헬스와 필라테스’, 짧은 이름 ‘헬스와필라테스’를 유지합니다.
- manifest.json은 이번 교체 파일에 포함하지 않았습니다. 이미 수정한 파일을 유지합니다.
- 이메일 안내 문구는 주황색·굵은 글씨이며 강제 줄바꿈 없는 기존 상태를 유지합니다.
- exercise-data.js, routine-components.js, style.css, images 폴더는 수정하지 않았습니다.
- JSON days/day 구조, 패턴/보너스 패턴, 이미지 루틴 fallback, 로그인 유지·로그아웃 방식은 바꾸지 않았습니다.

검증
- JavaScript 문법 검사 통과.
- 신규 가입 감지, 기존 선택/편집 상태 유지, 신규 회원 검색, 조회 중 선택 변경,
  늦은 응답 차단, 통신 실패/복구, 저장/화면 비활성 중 조회 보류,
  중복 조회/타이머 방지, 로그아웃/재로그인, 최초 회원 등록,
  루틴 배정 정보와 기존 수동 검색 동작 등 13개 모의 시나리오 통과.
- 기존 코드와 비교하여 수정 범위 및 최신 앱 이름/버전 보존을 확인했습니다.
- 실제 운영 DB에 계정을 만들거나 모바일 브라우저에서 직접 테스트한 것은 아닙니다.

배포 후 확인
1. 커밋·푸시 후 GitHub Pages 배포 완료를 기다립니다.
2. 관리자 앱은 이번 수정 코드를 적용하기 위해 한 번 새로고침합니다.
3. 관리자 화면을 화면에 보이게 두고 다른 브라우저나 휴대폰에서 새 테스트 회원으로 가입합니다.
4. 관리자 앱을 새로고침하지 않고 10초 안팎 기다린 뒤 신규 회원을 선택할 수 있는지 확인합니다.
5. 기존 회원을 선택하고 JSON 초안을 입력한 상태에서도 새 가입이 선택/초안을 초기화하지 않는지 확인합니다.
